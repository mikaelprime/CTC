Guía de respaldos

Cómo se protege la información y cómo recuperarla si hace falta.

1¿Qué se respalda y cuándo?

  • Toda la base de datos: estudiantes, inscripciones, pagos, cajas y bitácora.
  • Todas las noches a las 2:00 a. m. (hora de El Salvador), de forma automática.
  • Cada respaldo se guarda 30 días en GitHub.
  • Va cifrado: sin la contraseña de respaldo nadie puede abrirlo.
No hay que hacer nada a diario. Solo hay que configurarlo una vez (paso 2).

2Configurarlo (una sola vez)

En GitHub, dentro del repositorio: Settings → Secrets and variables → Actions → New repository secret. Crea estos dos:

NombreValor
BACKUP_DATABASE_URLLa cadena de conexión de Supabase (la misma que usa Render)
BACKUP_PASSPHRASEUna contraseña larga inventada por ti
Guarda la contraseña BACKUP_PASSPHRASE en un lugar seguro. Si se pierde, los respaldos no se pueden abrir.

3Comprobar que funciona

  1. En GitHub entra a la pestaña Actions.
  2. Elige Respaldo de la base de datos y pulsa Run workflow.
  3. Cuando termine en verde, abre la corrida: abajo, en Artifacts, está el archivo del respaldo.

4Descargar un respaldo

Actions → Respaldo de la base de datos → elige la fecha → Artifacts. Se descarga un archivo con nombre parecido a ctc_2026-09-28_0200.dump.gpg.

5Recuperar la información

Solo si se perdieron o dañaron datos. Necesitas PostgreSQL instalado en la computadora (trae pg_restore) y Git para Windows (trae gpg).

  1. Abrir el respaldo (pide la contraseña de respaldo): 
    gpg --output ctc.dump --decrypt ctc_2026-09-28_0200.dump.gpg
  2. Cargarlo en la base de datos: 
    pg_restore --clean --if-exists --no-owner --no-privileges --dbname "CADENA_DE_SUPABASE" ctc.dump
El paso 2 reemplaza los datos actuales por los del respaldo. Hazlo solo cuando estés seguro.

6Respaldo extra desde Supabase

Supabase también guarda copias propias en Database → Backups. Antes de un cambio grande en el sistema, conviene revisar que haya una copia reciente.
